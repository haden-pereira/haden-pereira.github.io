# AI Hallucinations Are Creating Real Security Risks

AI assistants can sound certain while being wrong. That certainty is dangerous when outputs are used to change code, run commands, or make security decisions.

## Quick risk examples
- Generated code that removes authentication checks.
- Fake CVE or patch links that waste triage time.
- Hallucinated remediation commands that delete logs or expose secrets.
- Polished phishing content or forged documents that aid social engineering.

## Simple defenses (do these now)
- Require human review before applying LLM-generated code or commands.
- Validate outputs automatically (URLs, commands, schema).
- Use retrieval with citations; reject outputs lacking sources.
- Sandbox and dry-run generated scripts before execution.
- Log model inputs/outputs and monitor for anomalies.

Minimal validation snippet:

```js
function isSafeUrl(url) {
  try { return new URL(url).protocol.startsWith('http'); } catch { return false; }
}
```

## Checklist
- [ ] Human review for LLM-sourced PRs
- [ ] Automatic validators for code/commands
- [ ] Retrieval with citations enabled
- [ ] Canary probes to detect hallucinations
- [ ] Incident playbook for hallucination events

Treat LLM outputs as untrusted inputs: verify, gate, and monitor. That keeps productivity benefits while reducing real security risk.

Practical next step: pick one LLM-enabled workflow this week and add a human-review gate. Assign an owner to monitor model logs and canaries, and iterate on validators as you learn.
